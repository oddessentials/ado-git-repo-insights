## Top-level deviation note (read first)

This spec is intentionally a **contract spec**, not a pure user-value spec. The locked decision to use the SC-05 reconciliation test (FR-2-04) as the sole authority for weekly-comments-aggregate parity, plus the cross-feature INV-07 closure obligation inherited from 310's spec, REQUIRE implementation-anchored references (file paths, schema field names, table column names) so the contract is executable and externally verifiable. Stripping those references would gut the spec's verifiability — the four contract-spec items below are therefore acknowledged deviations from the speckit template's pure-user-value norm, NOT defects the spec should be edited to fix.

The deviations are intentional, scoped to the fields listed below, and offset by:
- A user-facing User Stories section (P1 / P2 / P3) that is non-technical and stakeholder-readable.
- Success Criteria SC-1-01 through SC-1-04 that are technology-agnostic and user-focused.
- A clean separation: implementation references appear in Functional Requirements + Cross-feature Invariants + SC-1-05 (which is the cross-feature parity criterion) — the rest of the spec stays at user-value level.
