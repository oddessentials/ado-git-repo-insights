# Research (Phase 0)

**Status**: complete at spec-draft time. No `[NEEDS CLARIFICATION]` markers were introduced in the spec; every candidate research topic was resolved by the M1–M5 in-session investigation pass that preceded Pass 1.

This document consolidates the research findings as a planner-consumable reference. It does NOT re-open any spec decision.

## Research topic matrix

| Topic | Decision | Rationale | Alternatives considered |
|---|---|---|---|
| Delivery mechanism (inline vs lazy vs hybrid) | **Inline** — per-PR array embedded in each weekly rollup JSON. | M2 measurement: worst-case envelope at 500-PR truncation + 120-char enterprise titles + derived URLs ≈ 335–400 KB total rollup, well under the 500 KB per-file contract cap. No round-trip required on drill-down open. | **Lazy** (separate per-week artifact loaded on drill-down): extra round-trip, breaks instant-open SC-001; rejected. **Hybrid** (inline minimal tuple, lazy-load detail): added round-trip for the common case with no size benefit; rejected. |
| Truncation strategy | **Aggregator-side top-500 by `cycle_time desc`, stable tiebreak by `id asc`**. | M1 measurement: real seed max 464 PRs/week; 500 is a defensive ceiling above observed peak. Pre-truncation at aggregator keeps payload bounded. Filter-identity under truncation handled by the two-count truncation-indicator surface (FR-008 / FR-003). | **Full-list** (no aggregator cap): size risk at 1000+ PR weeks (M2 scenario D showed 622 KB projected). **Post-filter cap only**: same size risk. **Top-N by other sort key**: cycle_time is the UX-meaningful explanatory metric ("which PRs took longest"). |
| URL shape (persist vs derive) | **Derive client-side** from `pr.id + pr.repository_id` using the dimensions-artifact `repository_id → repository_name` mapping + VSS web context org/project. | Reduces per-record byte cost (~110 B saved per record at scale). Avoids persisting org/project paths in artifact. M4 confirmed the repositories dimension already carries name mapping. | **Persist full URL string**: wider payload, embeds org/project structure. **Persist partial URL**: splits the derivation burden awkwardly. |
| Filter support scope | **Supported: unfiltered, author-only, repository-only, author+repository. Unsupported: team, reviewer, comparison.** | Locked fields `{id, title, author_id, repository_id, cycle_time}` enable client-side filtering by author and repo without extending per-record schema. Team membership and reviewer association are list-valued and require either per-record dimension arrays (fattens record significantly) or separate dimension artifacts (new parity surface). Both are out of scope for first slice. | **Full filter matrix with expanded fields**: fattens record ~25% and adds complexity. **Disable drill-down entirely under any filter**: regresses Phase 1. **Best-effort partial filter**: violates filter-identity invariant. |
| Unsupported-filter UX (panel-denial vs section-gating) | **Section-gating** — panel opens as Phase 1 does under team/reviewer; only the new PR-level section is replaced with an inline explanatory message. Comparison mode preserves Phase 1 toast-denial unchanged. | Preserves Phase 1 aggregate drill-down access under team/reviewer filters (which is the current behavior). Avoids regressing the existing contract. Inline message is a content state of the stable PR-detail container, not a separate UX mechanism. | **Full-panel denial (Option A)**: regresses Phase 1 by removing aggregate-breakdown access under team/reviewer. **Silent section omission**: fails "no partial or approximate results" principle. **Advisory toast**: wrong UX semantic for a persistent gated state. |
| Empty-state handling (supported filter, zero matches) | **Distinct content state of the PR-detail container** — "No PRs match the active filter in this week." Renders normally alongside Phase 1 aggregate sections. | Zero matches is a legitimate result, not a gated state. Separate copy from unsupported-filter messages prevents UX conflation (FR-009 / FR-018). | **Hide section**: breaks stable-container contract. **Reuse unsupported-filter copy**: misleading. **Advisory toast**: wrong for a panel-open state. |
| Demo/public surface posture | **Strip at the single authoritative write boundary** — the strip gate lives INSIDE `promote_data` (at `build-demo-dataset.py:1044`) as its first step when destination equals `DOCS_DATA_DIR`. The gate removes `prs` / `_prs_truncated` / `_prs_cap` and fails the build on residue. Standalone-bypass in `generate-demo-data.py` is closed separately via `DEFAULT_OUTPUT_DIR` change + early-exit guard. | PR titles + IDs are tenant-sensitive content per the new privacy posture (FR-014). Extension reads them with tenant ADO permissions; demo/public surface has zero access rights. Gate-inside-promote_data is narrower than "don't emit" because emission drives the extension use case. Single authoritative boundary (one helper, one invocation site) matches QG-49. | **Don't emit at all**: breaks extension use case. **Conditional emission flag**: widens the producer surface; gate-at-publish is simpler and test-enforceable. **Duplicated gate at every caller**: violates QG-49 single-command-per-gate. **Redact titles only**: leaves URLs + IDs exposed, incomplete. |
| Snapshot semantics | **Accept "refresh-on-next-extract"** — PR content in rollups reflects DB state at aggregation time; updates when the next extract+aggregate cycle runs. | Matches existing pipeline snapshot cadence; no new cadence infrastructure needed. Tightening cadence would be a separate pipeline feature. | **Tighter refresh** (e.g., live re-fetch on drill-down open): breaks offline/static-artifact model; out of scope. **No snapshot commitment**: leaves future behavior undefined. |
| Filter-identity contract under aggregator truncation | **Rendered set may legitimately be a subset of the aggregate-attribution set when `_prs_truncated=true`**. Indicator surface (FR-017) displays both counts (`rendered_count` and `actual_filtered_count`) whenever they differ. | Strict equality is unachievable when aggregator pre-truncates by cycle_time and a filter selects PRs that fell outside the top-500. Two-count display is the user-visible reconciliation. When `_prs_truncated=false`, the sets are element-wise identical. | **Post-filter cap**: breaks the aggregator-truncation payload guarantee. **Relax filter-identity wholesale**: loses determinism under normal (non-truncated) weeks. |
| Privacy contract ordering | **Privacy-posture doc change lands in or before the commit that first produces a `prs` field**. | Prevents the branch's git history from ever containing PR-array-producing code without the documented posture. Auditor-safe. | **Doc after code**: leaves an audit gap in history. **Doc as separate PR later**: splits the atomic contract. |
| Stable-container pattern | **Single `PanelSection` variant with internal `contentState` discriminant** (4 values). | Phase 1 uses conditional-section-construction, but FR-020 locks a stable element identity — achievable only by always-rendering the container and swapping children. Single variant with discriminant avoids introducing 4 sibling variants that would break the stable-identity contract. | **4 separate variants**: breaks stable identity. **Conditional inclusion**: breaks stable identity. **Always-empty-wrapper + overlay**: more complex than discriminant. |
| Single authoritative filter-support predicate | **`classifyFilterState(filters, comparisonActive)` returning `{ classification: "comparison" \| "team" \| "reviewer" \| "supported" }`** with fixed precedence `comparison > team > reviewer > supported`. | Prevents call-site reconstruction (FR-024). Locked precedence (FR-026) prevents UI drift when multiple unsupported filters are simultaneously active. | **Boolean-per-filter helpers**: allows call-site precedence reconstruction; forbidden by FR-024. **Inline checks**: duplicates logic across call sites. |
